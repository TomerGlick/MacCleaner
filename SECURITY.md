# Security Policy

Mac Storage Cleanup deletes files and, if you install its optional helper, runs code as
root. Security reports are taken seriously.

## Supported Versions

Only the latest release receives security fixes. Older versions are not patched — please
update before reporting.

| Version | Supported |
| ------- | --------- |
| 1.5.x   | ✅        |
| < 1.5   | ❌        |

## Reporting a Vulnerability

**Do not open a public issue for a security problem.**

Report it privately through GitHub:

1. Go to the [Security tab](https://github.com/TomerGlick/MacCleaner/security).
2. Choose **Report a vulnerability**.
3. Describe the issue and how to reproduce it.

That opens a private advisory visible only to you and the maintainer. You can also reach
it directly at
<https://github.com/TomerGlick/MacCleaner/security/advisories/new>.

Helpful things to include:

- macOS version and app version
- Steps to reproduce, or a proof of concept
- What an attacker gains, and what access they need to start
- Whether the privileged helper was installed

## What to Expect

This is a single-maintainer project, so the honest timeline is:

- Acknowledgement within 7 days
- An assessment — confirmed, needs more information, or out of scope — within 14 days
- A fix in the next release for confirmed issues, sooner if the impact is severe

You will be credited in the release notes and the advisory unless you ask otherwise.
Please give a fix a reasonable window before disclosing publicly.

## Areas of Particular Interest

These are the parts where a bug would hurt most:

- **Privileged helper** (`MacCleanerHelper`) — a root daemon registered with
  `SMAppService`. It exposes one XPC method that runs `/usr/sbin/purge` with no arguments,
  and both ends pin each other by bundle identifier and team with
  `setCodeSigningRequirement`. Anything that lets another process drive it, or lets a
  substituted binary answer as the helper, is a serious finding.
- **Deletion paths** — any way to make the app delete outside what the user selected, or
  to slip past the safe list and protected-path checks.
- **Backups** — restoring a backup writing outside its intended destination, or a backup
  exposing file contents to other users on the machine.
- **Update check** — the app queries the GitHub Releases API and never downloads or
  installs anything. Anything that turns it into code execution is in scope.
- **Code signing and distribution** — the app is signed with a Developer ID certificate,
  hardened runtime enabled, and notarized. Reports about broken signature verification
  are welcome.

## Out of Scope

- The app needing administrator rights to free memory, or to delete files owned by the
  system. That is by design, and the helper is optional.
- Files deleted because the user selected them and confirmed the deletion.
- Locally built, unsigned or ad-hoc-signed copies of the app, where macOS refuses to
  register the helper. That is the operating system doing its job.
- Results from running the app on an unsupported macOS version.
- Reports generated by an automated scanner with no demonstrated impact.
